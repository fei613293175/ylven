## 实际操作与回读

- 公共管理员登录：`POST /admin/v1/auth/login` 返回 HTTP 201，身份为脱敏管理员 `admin`。
- 权限拒绝：无 Bearer 会话读取 `GET /admin/v1/conversations` 返回 HTTP 403，错误码 `permission_denied`。
- 会话列表：授权读取返回 HTTP 200，共 105 个真实持久化会话。
- 会话诊断：抽样会话 ID 仅记录 SHA-256 `248f9fa4a56154208701f39641f543acf195d149e7c327816531fd5a1c228c22`；详情返回 HTTP 200，包含 1 条用户消息、1 条助手消息和 1 个 `completed` run。
- 聊天指标：修复公开反向代理的精确路由后，`GET /internal/metrics/chat` 返回 HTTP 200 JSON，共 71 条指标，包含 `chat.run` 和 `chat.regenerate`；无授权请求仍返回 403。
- 审计：会话 API 回读 1,570 条审计事件；包含 `admin_login`、`conversation_created`、`message_run_started`、`message_run_completed`、`conversation_export_created`、`conversation_renamed`、`conversation_archived`、`conversation_temporary_created`、`message_feedback` 和 `speech_requested`。
- 最新审计事件标识：`c4b2f43867799fd4`、`9045d03321f742ed`、`690e1cbe22a86862`、`d7d0af47ff0a5d65`、`6d857e97278d589d`。

## 部署修正

首次实测发现 `/internal/metrics/chat` 被 Nginx SPA fallback 返回为 HTML。根因是 vhost 仅代理 `/internal/v1/`。Commit `920267d` 增加受限的精确路由 `location = /internal/metrics/chat`；服务器 `nginx -t` 通过并平滑 reload。复测确认授权 JSON、真实指标数据和未授权 403 均正确。

本证据使用真实公共入口、真实管理员权限、真实持久化数据和真实审计；不使用 mock、静态成功页或测试夹具冒充后台验收。
