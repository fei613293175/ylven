# 21 错误码、重试、幂等与失败处理

## 1. 统一错误信封

所有 JSON API 错误返回 `error.code`、面向用户或开发者的 `message`、可供查日志的 `request_id`、布尔值 `retryable` 和可选 `details`。Android 不根据英文 message 判断业务分支，只根据稳定错误码。后台可查看内部堆栈，但对外响应不得返回 Secret、SQL、上游凭据、内部主机名或跨用户资源信息。

## 2. 重试边界

只有明确标记 retryable 的网络、供应商超时、队列投递和幂等写失败允许自动重试。验证码错误、权限不足、预算超限、文件不支持和业务冲突不得无条件重试。客户端重试必须复用幂等键或 Run ID；服务端使用指数退避、抖动、最大次数和总时间预算。

## 3. 幂等要求

用户创建、订单、支付回调、退款、账本交易、充值投影、异步任务、Webhook 和 API Key 创建等写操作必须支持幂等。相同幂等键与相同请求摘要返回相同结果；相同键与不同请求体返回 `IDEMPOTENCY_CONFLICT`。幂等记录需保存范围、请求摘要、结果引用、状态和过期策略。

## 4. 流式聊天失败

Run 从创建、排队、连接、流式、完成、失败、取消形成可持久化状态。SSE 事件拥有单调 event_id，Android 使用 `Last-Event-ID` 或等价游标恢复。上游中断时保留已接收内容和真实模型来源；系统不能静默将剩余回答切换另一模型。用户明确选择回退时创建新 Run/分支。

## 5. 异步任务失败

图片、PPT、文件解析和索引任务记录输入版本、幂等键、尝试次数、租约、心跳、进度、错误码和结果。重试必须确认任务是否可安全重复；失败达到上限进入死信，后台可人工重试或终止。收费任务在失败/取消时按已发生真实成本结算或解冻，不能重复扣费。

## 6. 财务失败

支付状态和额度发放状态分离。支付已成功但账本或 Sub2API 投影失败时，订单保持 `PAID/CREDIT_PENDING` 并由 Worker 重试；不能让用户再次付款。退款也使用独立状态、账本冲正和投影同步。所有人工补偿记录原因、审批人和关联事故。

## 7. 错误目录

机器可读目录为 `contracts/error-code-catalog.yaml`。实现新增错误码前必须更新目录、OpenAPI 示例、Android 映射和测试；禁止多个服务用同一个字符串表达不同含义。
