# 11 统一身份、邮箱注册登录、Turnstile 与账号安全

## 1. 本章是身份功能的唯一实现口径

首期 YLVEN Android App 使用邮箱作为账号标识。不得将手机号、用户名或 Sub2API 账号作为注册主键。用户注册时必须填写邮箱、登录密码、确认登录密码；普通登录页面首期只提供“邮箱 + 邮箱验证码”方式。注册与登录在向后端发起发送验证码或确认操作前，必须先完成安全验证弹窗。

注册时设置的密码必须安全保存，但首期不在普通登录页开放密码登录。该密码用于未来开启密码登录、账号恢复、导出数据、创建高权限 API Key、修改主邮箱等高风险操作的二次验证。是否开放密码登录由管理后台功能开关控制，默认关闭。

## 2. 身份体系边界

### 2.1 YLVEN 是身份权威

YLVEN 后端生成不可变 `user_id`（UUID/UUIDv7）和可展示数字 `uid`。邮箱可以修改，因此邮箱不能承担跨系统永久绑定键。Sub2API、未来官方 API 供应商映射、设备、会话、钱包、项目和作品均关联 YLVEN `user_id`。

### 2.2 密码和验证码不得同步到 Sub2API

Sub2API 用户只通过不可变外部 subject 绑定。YLVEN 不向 Sub2API 写入用户密码、验证码或完整登录会话。未来单点登录使用 OIDC/OAuth 2.0 授权码流程及 PKCE，不共享密码表。

## 3. 注册完整流程

### 3.1 Android 页面字段

1. 邮箱地址；
2. 登录密码；
3. 确认登录密码；
4. 同意服务条款与隐私政策的勾选项；
5. “注册”主按钮；
6. 已有账号时跳转登录入口。

### 3.2 本地校验

点击注册前必须完成本地校验：

- 邮箱去除首尾空格并转换为规范形式，但不得擅自修改本地部分字符；
- 邮箱格式合法且长度在后端规定范围；
- 密码满足后台配置的最低长度和复杂度；
- 两次密码完全一致；
- 已勾选服务条款；
- 不在请求进行中重复提交。

本地校验只用于即时反馈，后端必须重复执行全部校验，不能信任客户端结果。

### 3.3 安全验证弹窗

点击“注册”后弹出安全验证底部弹层或全屏 WebView，加载 `auth.orbexa.cc` 上的 Cloudflare Turnstile 页面。Android 获取到 Turnstile token 后，将 token 与注册意图一并提交后端。后端必须调用 Turnstile Siteverify 验证 token，并校验预期 action、hostname、时效和单次使用状态。

客户端不得仅依据 JavaScript 回调判定安全验证成功。Turnstile 私钥只保存在后端密钥管理中。

### 3.4 发送注册邮箱验证码

安全验证通过后调用注册挑战接口。后端：

1. 对邮箱、设备、IP、Turnstile action 和请求指纹执行速率限制；
2. 使用统一响应避免泄露邮箱是否已注册；
3. 生成密码学安全的 6 位数字验证码；
4. 只保存验证码哈希、用途、尝试次数和过期时间；
5. 创建 `pending_registration` 或注册挑战记录，不创建正式用户；
6. 通过事务邮件供应商发送验证码；
7. 返回挑战 ID、脱敏邮箱、重发倒计时和过期时间。

验证码建议 10 分钟失效；同一挑战连续错误达到上限后必须失效。具体数值由后台配置并有安全边界，不允许任意设置为 0 或无限。

### 3.5 验证验证码并创建用户

用户输入验证码后提交挑战 ID 和验证码。后端在单一事务中：

1. 锁定挑战记录并检查用途、状态、过期时间、尝试次数；
2. 常量时间比较验证码哈希；
3. 再次检查邮箱是否已注册，防止并发重复创建；
4. 使用 Argon2id（或经安全评审批准的等效算法）哈希密码；
5. 创建 `users`、`user_profiles`、个人工作区、默认偏好和审计事件；
6. 将挑战标记为已消费；
7. 签发短期访问令牌和可轮换刷新令牌；
8. 异步创建或确保 Sub2API 用户映射，但 Sub2API 暂时不可用不得回滚 YLVEN 注册；
9. 返回最小用户资料和会话令牌。

任何重试必须幂等。相同挑战成功后重复提交，应返回“已经完成”或同一注册结果，不能创建第二个用户。

## 4. 邮箱验证码登录完整流程

### 4.1 登录页面

首期登录页包含：邮箱输入、获取验证码按钮、验证码输入区、登录按钮、注册入口、隐私条款入口。验证码输入区可在发送成功后展开。

### 4.2 请求验证码

用户输入邮箱并点击获取验证码后：

1. Android 先显示 Turnstile 安全验证；
2. 安全验证成功后调用登录挑战接口；
3. 后端无论邮箱是否存在都返回相同的表面响应；
4. 对已注册且状态允许登录的账号发送登录验证码；
5. 创建用途为 `LOGIN_EMAIL_OTP` 的挑战；
6. 返回挑战 ID、倒计时和脱敏邮箱。

不得通过响应状态、耗时或文案暴露邮箱是否存在。后台审计日志可以记录真实原因，但普通用户响应必须统一。

### 4.3 验证并登录

验证码正确后：

- 检查用户状态、封禁、删除冷静期和风险策略；
- 创建新登录会话；
- 记录设备、客户端版本、IP 风险摘要和登录时间；
- 更新最后登录时间；
- 签发访问令牌与刷新令牌；
- 在高风险情况下要求额外验证或拒绝登录；
- 不得把邮箱验证码当作长期令牌保存。

## 5. Token 与设备会话

- Android 访问令牌短期有效，刷新令牌较长期有效并支持轮换；
- 刷新令牌保存在 Android Keystore 加密容器中，不保存于普通 SharedPreferences；
- 后端保存刷新令牌家族、哈希、设备和撤销状态；
- 每次刷新使旧 token 失效，检测到旧 token 重用时撤销整个家族；
- 用户可在“我的—登录设备”查看和撤销其他设备；
- 管理员封禁用户、用户改主邮箱或执行安全重置时，可撤销全部会话；
- API Key 与 App 登录 token 完全分离。

## 6. 密码策略与高风险操作

密码最少 10 个字符，允许长密码和密码管理器粘贴，不强制频繁更改。后台可调整最低长度，但不得降低到安全底线以下。禁止明文、可逆加密或日志记录密码。

以下操作需要近期认证：

- 修改主邮箱；
- 修改或重置密码；
- 创建无严格预算限制的开发者 Key；
- 导出全部用户数据；
- 注销账号；
- 修改支付或退款相关配置；
- 管理员敏感操作。

近期认证可以使用邮箱验证码、已设置密码和后续 MFA 中至少一种，由风险策略决定。

## 7. 邮件基础设施

邮件供应商必须通过适配器接入。至少支持主供应商和备用供应商配置，包含发送域、From 地址、回复地址、模板版本、区域、超时和重试。DNS 必须配置 SPF、DKIM、DMARC；生产环境不得使用个人邮箱 SMTP 作为主要通道。

邮件任务进入高优先级队列。发送失败要区分暂时失败、永久退信、投诉和供应商限流。验证码邮件不能无限重试；超过有效期后停止发送并标记失败。

## 8. 管理后台菜单

`用户与身份 / 认证配置`：

- 注册开关；
- 允许邮箱域规则；
- 密码最低长度；
- 邮箱验证码有效期和重发间隔；
- 每邮箱、IP、设备速率限制；
- Turnstile site key、action、允许 hostname（密钥仅显示掩码）；
- 邮件供应商与模板；
- 密码登录功能开关；
- 会话有效期与设备上限。

`用户与身份 / 登录挑战`：只显示脱敏邮箱、用途、结果、风险评分、IP 摘要、设备和时间，不显示验证码。

`安全中心 / 认证风险`：异常发送、暴力尝试、账号枚举、异常设备、退信和投诉。

所有配置变更必须有版本、操作者、时间、差异、发布和回滚记录。

## 9. 必测场景

1. 注册成功并自动登录；
2. 邮箱格式、密码不一致和条款未勾选；
3. Turnstile 失败、过期、重复使用、action/hostname 不匹配；
4. 邮件发送暂时失败及重试；
5. 验证码错误、过期、超过尝试上限、已消费后重放；
6. 同一邮箱并发注册只生成一个用户；
7. 已注册邮箱请求注册时不泄露敏感状态；
8. 不存在邮箱请求登录时不产生可枚举响应；
9. 刷新令牌轮换和重用检测；
10. 用户被封禁、删除冷静期、设备撤销；
11. Sub2API 不可用时 YLVEN 注册仍成功且创建同步任务；
12. Android 进程被杀后仍能安全恢复登录状态。
