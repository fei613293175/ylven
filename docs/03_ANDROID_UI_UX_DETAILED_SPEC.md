# 03 Android 前端页面与 UI/UX 详细规格

## 1. 技术与版本基线

- 原生 Android，Kotlin 2.4.10。
- `compileSdk` 与 `targetSdk` 固定为 Android 17 / API 37；`minSdk` 固定为 API 26。
- Jetpack Compose 使用稳定 BOM `2026.06.00`；禁止生产模块引入 Alpha 或 Beta Compose 组件。
- Material 3、Navigation、Lifecycle、Room、DataStore、WorkManager、OkHttp、Retrofit、Kotlin Coroutines。
- 架构采用单向数据流：UI State、UI Event、Reducer/ViewModel、Repository、Data Source；禁止在 Composable 中直接调用网络或数据库。
- 使用 Gradle Version Catalog 统一锁定依赖版本。

## 2. 设计 Token

所有页面必须引用 Token，不允许重复写具体数值。

### 2.1 间距

| Token | 值 | 用途 |
|---|---:|---|
| `space_1` | 4dp | 图标内部、小标签间距 |
| `space_2` | 8dp | 紧凑组件间距 |
| `space_3` | 12dp | 卡片内部相邻项 |
| `space_4` | 16dp | 页面左右边距、标准间距 |
| `space_5` | 20dp | 较大组件间距 |
| `space_6` | 24dp | 页面区块间距 |
| `space_8` | 32dp | 大区块和空状态 |

### 2.2 圆角

| Token | 值 |
|---|---:|
| 小标签 | 8dp |
| 普通按钮/小卡片 | 12dp |
| 主卡片 | 16dp |
| 输入框 | 24dp |
| 底部弹层 | 28dp |
| 圆形图标按钮 | 50% |

### 2.3 字体

| 样式 | 字号/行高 | 字重 |
|---|---|---|
| Display | 28sp / 36sp | 600 |
| Page Title | 24sp / 32sp | 600 |
| Section Title | 20sp / 28sp | 600 |
| Card Title | 17sp / 24sp | 600 |
| Body | 16sp / 24sp | 400 |
| Body Small | 14sp / 20sp | 400 |
| Label | 12sp / 16sp | 500 |

正文禁止使用 18sp 以上造成聊天页面松散；用户启用系统大字体时必须通过自适应布局而不是截断。

## 3. 导航规则

- 一级页面使用四栏底部导航。
- 聊天详情、图片编辑、PPT 编辑、文件预览和敏感安全页隐藏底部导航。
- 所有二级页必须支持系统返回、手势返回和状态保存。
- Android 17 大屏与可调整窗口必须使用 Window Size Class，自适应双栏或导航栏，不锁定竖屏。

## 4. 认证页面

### 4.1 注册页

字段顺序固定：邮箱、登录密码、确认登录密码。密码框带显示/隐藏按钮和强度提示。点击“注册”后：

1. 本地校验邮箱格式、密码规则和两次密码一致。
2. 弹出不可绕过的安全验证底部弹层，加载 Turnstile 移动端 WebView 页面。
3. 验证成功后后端发送注册邮箱验证码，进入验证码页面。
4. 用户输入 6 位验证码；支持自动聚焦、粘贴完整验证码、倒计时和重新发送。
5. 后端验证成功后创建账户并自动登录。

不得在安全验证完成前发送注册验证码。不得在验证码未验证时创建“待激活用户”占用正式 UID，可创建短期注册事务记录。

### 4.2 登录页

首期页面只显示邮箱和“获取验证码/继续”按钮，不显示密码输入框。点击继续后先完成安全验证，再发送登录验证码。验证码验证成功后建立设备会话。

页面底部提供“注册账户”“遇到问题”“隐私与服务条款”入口。后台开关未来可增加密码登录，但默认关闭。

### 4.3 安全验证弹层

- 使用 28dp 顶部圆角底部弹层。
- WebView 只允许 `auth.orbexa.cc` 和 Cloudflare Turnstile 必要域名，不允许任意导航。
- 显示加载、完成、失败、网络不可用和重新尝试状态。
- 验证 Token 只能提交给 YLVEN 后端，Android 不直接调用 Siteverify。

## 5. AI 首页与聊天

### 5.1 首页空状态

顶部高度控制在 56dp；快捷卡片最多 6 个；最近会话最多展示 5 条，更多进入抽屉。输入框始终固定在安全区域上方，不被键盘遮挡。

### 5.2 聊天消息

- 用户消息靠右使用浅色或提升面气泡，最大宽度屏幕 82%。
- AI 消息靠左全宽展示，不使用巨大气泡。
- AI 回答上方显示供应商图标、模型名、推理档位和工具状态；下方显示复制、朗读、重答、换模型、反馈等操作。
- 代码块、表格、引用、文件、图片、工具调用和作品分别使用独立组件，不把全部内容渲染为普通 Text。
- Markdown 渲染必须支持标题、列表、链接、代码、表格、数学表达式占位和流式增量更新。
- 不展示或伪造模型内部思维链。允许显示“推理中”、已选择档位、耗时和推理 Token 数（上游提供时）。

### 5.3 输入框

- 默认一行，最多展开至约 6 行。
- 左侧附件按钮；右侧语音和发送/停止按钮。
- 附件以可删除 Chip 显示，上传未完成时禁止发送或由后端明确支持延迟绑定。
- 流式生成时发送按钮变为停止按钮。
- 网络断开后显示恢复条，使用事件游标续传，禁止重复创建回答。

### 5.4 模型选择器

第一层按“智能推荐、GPT、Claude、Grok”分组；第二层展示模型卡片。每张卡片显示模型用途、速度、已验证能力和当前服务状态。高级区域显示当前模型实际支持的推理档位，不显示不支持的档位。

切换时必须提供：

- 仅用于本次回答；
- 设为当前会话默认模型。

## 6. 工作页

- 顶部分段标签 `工具/项目/作品/任务`。
- 工具卡片使用统一 16dp 圆角和 48dp 图标容器。
- 图片和 PPT 创建使用向导式页面，不使用一个无限长表单。
- 任务列表明确显示排队、运行、进度、成功、失败和取消。
- 作品卡片显示类型、缩略图、标题、更新时间、版本和项目归属。

## 7. 发现页

发现页由服务端返回布局数据。客户端只支持经过白名单定义的组件类型，例如 Hero、Grid、List、Banner、SectionHeader，禁止服务端下发任意 HTML 或脚本。

## 8. 我的页面

顶部资料卡高度约 104～120dp。菜单分为内容、商业与开发者、AI 设置、安全与数据、系统五组；每组最多 6～8 项，禁止将所有功能堆在一个无分组列表中。

## 9. 全局状态

每个主要页面必须设计并实现：

- 首次加载骨架；
- 空状态；
- 局部加载；
- 可恢复错误；
- 权限不足；
- 套餐/额度不足；
- 服务不可用；
- 离线；
- 数据已删除或过期；
- 需要升级 App。

不得只在成功状态下绘制效果图和页面。

## 10. 可访问性与性能

- 最小点击区域 48dp。
- 所有图标按钮有 contentDescription。
- 颜色对比满足 WCAG AA；状态不能仅依赖颜色表达。
- Lazy 列表必须提供稳定 Key 和内容类型。
- 图片使用缩略图、缓存和渐进加载；大文件不进入内存整体读取。
- 聊天流式更新节流到合适帧率，避免每个字符触发整个列表重组。
