# 20 既往项目踩坑与强制对策

## 1. 长会话后遗忘早期规则

**问题**：连续开发多个版本后，Codex 忘记 APK、功能清单、测试清单和桌面交付。  
**对策**：一阶段一会话；短 AGENTS；CURRENT_PHASE；Feature Map；发布和校验脚本；CI。文字提醒不是完成依据。

## 2. 治理检查代替开发

**问题**：小版本连续 2～3 天反复 doctor、状态和证据检查，实际功能未完成。  
**对策**：禁止 Governance V5.0；只做一次初检；连续两轮无代码/测试产出时必须定位阻塞；开发中相关测试、阶段末全量测试。

## 3. 版本拆得过小

**问题**：32 个版本导致会话、交付和治理开销大于开发。  
**对策**：P00～P13 十四个实质阶段；每阶段是可验收垂直切片，不为一个按钮创建版本。

## 4. 前端壳和假数据冒充完成

**问题**：页面看似存在，后端、数据库和后台未接，后期集中返工。  
**对策**：Feature ID 一一映射前端、API、服务、表、后台和测试；完成定义禁止永久假数据。外部服务可 mock，但必须有真实 Adapter 和契约测试。

## 5. UI 最后统一补导致漂移

**问题**：字号过大、间距和圆角不一致、页面布局变形。  
**对策**：P00 建立 Design Tokens 和组件；每阶段同步完成 UI；Compose 页面禁止散落硬编码；支持字体放大、小屏和深色。

## 6. 只根据截图而缺少参数

**问题**：模型自由猜测尺寸和状态。  
**对策**：UI 文档固定层级、状态、Token 和行为；效果图只作为视觉参考，组件参数和 Feature Map 是实现基线。

## 7. App 直接连接中转站

**问题**：密钥泄漏、无法统一会话/文件/计费、无法迁移官方 API。  
**对策**：Android 只连接 YLVEN BFF；Sub2API 放在 Adapter 后；所有密钥服务端保存。

## 8. 模型能力写死

**问题**：不同供应商推理档位和文件能力不一致，上游变化导致 App 报错。  
**对策**：Model Registry + Capability Registry + Probe；App只显示后台配置且实际探测通过的能力。

## 9. 静默换模型

**问题**：回答来源不透明，用户选择被违反。  
**对策**：无明确授权不自动回退；每条回答保存并显示真实供应商、模型、推理和通道。

## 10. 所有消息只存 Markdown

**问题**：无法管理图片、文件、工具、引用和作品版本。  
**对策**：messages + message_parts + runs + tool_calls + citations + artifacts。

## 11. 每个 Token 写数据库

**问题**：数据库写放大和锁压力。  
**对策**：事件短期缓冲，最终合并落库，必要时分段 checkpoint。

## 12. 两套余额/支付互相同步

**问题**：重复充值、退款不一致、余额覆盖。  
**对策**：YLVEN 单一支付和账本；Sub2API 仅执行投影；单向命令和使用回流；幂等与对账。

## 13. 将余额做成一列

**问题**：套餐、赠送和充值无法到期、退款或解释。  
**对策**：不可变账本 + credit buckets + 可重建余额投影。

## 14. 过早微服务化

**问题**：Codex 时间消耗在服务发现、联调和分布式事务。  
**对策**：模块化 Core + 独立 AI Runtime/Gateway/Worker；指标证明瓶颈后再抽服务。

## 15. 外部密钥阻塞全部开发

**问题**：Codex 等待 DNS/密钥而停工。  
**对策**：OWNER_ACTIONS + mock + feature flag；只阻塞真实联调，不阻塞代码和测试。

## 16. 没有断线恢复

**问题**：Android 切后台、网络波动后回答丢失。  
**对策**：Run ID、SSE event ID、短期事件缓存、服务端最终状态和客户端重连。

## 17. 文件永久绑定供应商 ID

**问题**：切换模型或供应商后文件不可用。  
**对策**：原文件永久保存在 R2，供应商 file ID 只是可过期映射。

## 18. PPT 只保存二进制

**问题**：无法单页编辑和版本追踪。  
**对策**：Deck JSON 为可编辑权威，PPTX/PDF/预览为派生结果。

## 19. 公开个人订阅中转作为商业 API

**问题**：账号、条款和服务连续性风险。  
**对策**：当前线路标记 TEST/SUBSCRIPTION_PROXY；生产商业开放前切官方或授权 API；Android/API 协议不绑定线路。

## 20. 使用 latest 和无回滚升级

**问题**：Sub2API/依赖升级静默破坏。  
**对策**：版本固定、staging 契约回归、备份、不可变镜像和回滚记录。

## 21. 测试报告只写结论

**问题**：写“测试通过”但无命令和证据。  
**对策**：TESTS.md 记录命令、时间、环境、真实结果和跳过原因；发布脚本校验。

## 22. 后台只是列表

**问题**：系统不可配置、不可观测、不可审计。  
**对策**：每个领域同时设计配置、操作、指标、异常、审计、版本和回滚；Feature Map 中必须有后台菜单。
