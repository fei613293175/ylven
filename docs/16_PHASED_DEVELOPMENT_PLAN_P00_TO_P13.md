# 16 P00～P13 阶段开发计划

## 1. 阶段设计原则

本项目采用 14 个有实质交付的阶段，而不是几十个过小版本。每个阶段都必须形成可安装 APK、可访问后台进展、功能清单、测试清单、变更记录、构建信息和校验和。一个阶段内允许多个代码提交，但只在完成阶段验收时生成正式阶段交付。

Codex 每个阶段使用独立或干净的新会话。阶段状态只使用 `TODO`、`DOING`、`BLOCKED`、`DONE`。不得创建 Attempt 状态机，不得因非关键外部密钥阻塞整个阶段。

## 3. P00 工程基座和能力证明

- 初始化单仓库或明确多目录结构；
- Android Compose Shell、主题、四栏占位和环境切换；
- Go Core API、AI Runtime、Worker、Scheduler 基础工程；
- Vue 管理后台和开发者中心 Shell；
- PostgreSQL/Redis/NATS/R2 抽象、迁移和健康检查；
- Sub2API 适配器与能力探测命令；
- 文本、流式、取消、视觉、文件、图片生成能力矩阵；
- OpenAPI、Feature Map、错误码、日志和 CI 基线；
- 第一份可安装 Shell APK。

P00 不应伪装完整功能，但基础链路、构建、自动测试和发布脚本必须真实运行。

## 4. P01 身份后端和后台

实现用户、身份挑战、邮件任务、Turnstile Siteverify、密码哈希、会话、设备、RBAC、审计和后台认证配置。通过后端和后台集成测试证明注册/登录挑战安全，Android 暂可使用调试页面调用。

## 5. P02 Android 注册登录

实现启动、登录、注册、安全验证 WebView、邮箱验证码、自动登录、刷新、退出、设备管理、网络错误和无障碍。真机必须验证验证码键盘、深链返回、后台恢复和弱网。

## 6. P03 核心聊天

实现自己的 conversation/message/run/event 模型、SSE、停止、断线恢复、历史、重命名、删除/归档、标题生成、复制/分享、反馈和 Room 缓存。只接入一个经过 P00 验证的文本模型作为默认线路，先确保聊天链路可靠。

## 7. P04 多模型、推理和对比

动态模型目录、能力注册、推理档位映射、会话默认与单次临时模型、模型来源标签、换模型重答、分支、多模型并发对比、综合回答、健康状态和透明回退。后台可实时上下架/排序/配置模型。

## 8. P05 文件和视觉

R2 预签名上传、附件状态、安全检查、图片识别、PDF 和 Office 解析、资料库、消息附件、文件引用、上传恢复、配额和后台文件管理。只显示能力探测通过的模型/格式。

## 9. P06 项目和知识库

项目 CRUD、项目指令、项目会话/文件/作品、解析分块、pgvector、检索、引用、上下文预算、项目搜索和后台索引诊断。避免无条件加载全部文件。

## 10. P07 图片工作台

图片生成、编辑、参考图、参数、异步任务、进度、取消/重试、冻结/结算、作品版本、下载、继续编辑和后台模型/任务管理。

## 11. P08 PPT 工作台

向导、参考资料、大纲、模板、Deck JSON、PPT Worker、PPTX、PDF、页面预览、单页修改、版本、下载、模板后台和渲染诊断。所有中文由确定性渲染，不依赖图片模型写字。

## 12. P09 四栏产品整合

工作页“工具/项目/作品/任务”、动态发现、个人资料、默认模型、自定义指令、记忆开关、通知、主题、数据导出、App 更新、帮助反馈。消除占位页和断链，统一空/加载/错误状态。

## 13. P10 套餐、钱包和账本

产品、价格、订阅、权益、额度桶、不可变账本、订单/支付抽象、用量计费、预算、Sub2API 用户映射和余额/套餐投影、对账后台。首期可使用测试支付或管理员测试充值，但财务模型必须完整，不能写假余额。

## 14. P11 开发者平台

YLVEN Developer Gateway、OpenAI 兼容基础接口、原生 API、API Key、预算、IP 白名单、限流、日志、Playground、模型/价格文档、用量、共享余额和 YLVEN OIDC/Sub2API SSO 预备。个人订阅通道不得作为对外商业生产线路。

## 15. P12 性能、安全和运维

负载模型、普通 API/SSE/队列压测、供应商隔离、熔断、降级、WAF、秘密扫描、文件沙箱、审计、Prometheus/Grafana、日志/追踪、备份、恢复演练、事故和运行手册。

## 16. P13 最终加固

全功能回归、数据迁移测试、升级/回滚、官方 API Adapter 接入或 mock 演练、订阅通道到官方通道切换、APK 真机矩阵、后台权限审计、灾难恢复、数据导出/删除、成本和容量评估、已知限制及商业开放前待办。

## 17. 阶段推进规则

- `CURRENT_PHASE.yaml` 是唯一当前阶段；
- Codex 只实现该阶段文档和 Feature Map 指定功能；
- 开发中运行相关模块测试，阶段末运行全量必要测试；
- 连续两次工作没有代码/测试/明确阻塞产出时，停止泛化检查并定位具体阻塞；
- 外部密钥缺失写 `OWNER_ACTIONS.md`，用 mock 或关闭功能继续其余工作；
- 发布脚本成功后才可将阶段标记 DONE；
- 不自动开始下一阶段，项目所有者完成 APK/后台体验后再通过继续提示进入下一阶段。
