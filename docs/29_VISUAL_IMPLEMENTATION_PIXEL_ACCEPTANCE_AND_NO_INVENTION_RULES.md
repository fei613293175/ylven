# 29 — 像素级实现、验收与禁止臆造规则

## 1. 三类权威来源

1. **功能权威**：Feature ID、OpenAPI、数据模型、权限、计费和阶段合同。
2. **数值权威**：`ui-design-tokens.yaml` 与逐页 resolved contract。
3. **视觉权威**：状态对应的已批准效果图。

效果图中的虚拟文字、余额、模型、文件、头像和按钮名称不能改变功能合同。功能合同中没有的行为不得因效果图出现而实现。

## 2. 像素验收标准

- 页面尺寸、边距、固定高度、圆角、字号、行高和组件位置：目标误差 `0dp/0px`；
- 受真实字体渲染影响的字形边缘允许抗锯齿差异，但字号、行高、字重、基线和容器位置必须一致；
- 颜色使用 Token 精确值；不得“接近”；
- 动态内容允许高度变化，但必须遵循最小/最大尺寸、换行和溢出合同；
- 320/360/384/411dp 宽度、字体缩放、深浅主题和系统 Insets 必须验证；
- 每个状态都要有运行截图，不得只截成功态。

## 3. 功能不可由效果图生成

- 效果图中没有 Interaction ID 的控件不能点击；
- 效果图中出现的虚拟标签不能被写成后台固定枚举，除非合同已经定义；
- 效果图没有展示的错误码、权限和计费仍按开发文档实现；
- 当效果图与功能文档冲突时停止该局部页面，提出合同变更；不得静默选择一方。

## 4. 视觉差异报告

阶段交付必须生成 `VISUAL_DIFF_REPORT.md`，逐状态记录：效果图 SHA、运行截图、设备宽度、主题、字体缩放、差异区域、原因、修复提交或批准人。禁止使用“基本一致”“差不多”等不可验证结论。

## 5. 防漂移机制

- 每个 Work Packet 重复关键数值；
- 每个阶段重复关键数值和 Page ID；
- AGENTS 与 Spec Kit 模板要求读取 UI 合同；
- CI 运行 Planning/Release 两种 UI 校验；
- Release 缺少截图索引、差异报告或合同报告时失败；
- 新增页面但未分配 Page ID、State ID、效果图和 Feature ID 时失败。

## 阶段 UI 证据固定目录

真实阶段发布前，Codex 必须把视觉证据放在以下固定位置，不得临时改名或散落到桌面：

```text
build/ui-evidence/<Phase>/
├── screenshots/
│   ├── <StateID>.png
│   └── ...
└── VISUAL_DIFF_REPORT.md
```

- 每个绑定 State ID 必须恰好对应一张独立运行截图；文件名必须是 `<StateID>.png`。
- `VISUAL_DIFF_REPORT.md` 必须逐 State ID 记录已批准效果图 SHA、运行截图、设备/主题/字体缩放、差异和处理结果，并包含 `- Result: PASS`。
- `scripts/05_RELEASE_PHASE.ps1` 默认读取 `build/ui-evidence/<Phase>`；缺少任一状态、效果图未 APPROVED、SHA 不一致或存在未解释差异时，阶段发布失败。
- 桌面交付是发布脚本生成的副本，不是视觉证据的权威来源。
