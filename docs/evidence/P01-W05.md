# P01-W05 Evidence

- Work Packet: `P01-W05`
- Feature IDs: `P01-024` through `P01-028`
- Scope: user status controls, administrator RBAC/session security and email notification templates

## Implementation

- `POST /admin/v1/users/{userId}/status` updates active/disabled state, revokes sessions on disable and records audit evidence.
- `GET|POST /admin/v1/rbac/roles` stores role permissions; `POST /admin/v1/auth/login` creates bearer-backed administrator sessions.
- `POST /admin/v1/security/step-up` verifies the administrator credential and issues a five-minute, session-bound, one-time token.
- `GET|PUT /admin/v1/notifications/email-templates` returns versioned templates and delivery records; stale writes return a conflict.
- Migration `backend/db/migrations/0003_p01_admin_rbac_notifications.sql` defines roles, admin users/sessions, step-up challenges and notification tables.
- Admin web routes `YL-M-027`, `YL-M-037`, `YL-M-038`, `YL-M-039`, `YL-M-040` use the approved 1440px shell and real API data.

## Security boundaries

- No raw admin password, token, API key or server credential is committed.
- Access/refresh/admin/step-up values are stored as digests; the legacy `X-Admin-Role` header is rejected.
- Bootstrap uses `OWNER_ADMIN_EMAIL` and `ADMIN_BOOTSTRAP_PASSWORD` only at runtime.
