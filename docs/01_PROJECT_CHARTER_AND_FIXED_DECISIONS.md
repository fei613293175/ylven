# 01 项目章程与不可静默改变的决策

## 1. 产品使命

YLVEN 是一套以 Android 为首发客户端、以自建业务后端为数据权威、以多模型调度为核心能力的商业级 AI 工作平台。首期服务对象为项目所有者本人，但所有身份、权限、数据隔离、计费、审计和扩容设计必须满足未来多用户开放的要求。系统不得退化为直接调用 Sub2API 的套壳客户端。

## 2. 固定范围

- Android 原生 App，一级导航固定为：首页、工作、发现、我的。
- 专业管理后台、开发者中心、公共 API、PostgreSQL 数据库、Redis/NATS、R2 文件与作品存储。
- 首页覆盖独立会话、流式聊天、历史、模型与推理选择、多模态、文件和模型来源透明。
- 工作覆盖项目、知识库、图片、PPT、作品和异步任务。
- 发现由后台动态配置，不交付永久空白占位页。
- 我的覆盖账号、套餐、钱包、用量、AI 偏好、设备、安全、数据和开发者 API。

## 3. 身份决策

注册必填邮箱、登录密码、确认登录密码。提交注册前必须完成安全验证；安全验证通过后发送邮箱验证码，验证码确认后才创建用户。普通登录采用邮箱 + 邮箱验证码，发送验证码前同样完成安全验证。密码使用强哈希保存，不能明文、可逆加密或写日志。未来 YLVEN 通过 OIDC 为 Sub2API 提供单点登录，不同步密码。

## 4. AI 与数据权威

Android 只请求 YLVEN Mobile API。YLVEN 保存用户、会话、消息、项目、文件、作品、订单、账本和权益；Sub2API 仅作为当前上游账号池、路由、实时计量、API Key 和限流执行层。任何供应商 response_id、file_id 或 conversation_id 都只能作为可失效外部引用，不能成为 YLVEN 主键。

## 5. 商业边界

当前 ChatGPT、Claude、Grok 订阅中转线路只用于内部测试，必须在配置和日志中标记 `TEST/SUBSCRIPTION_PROXY`。未来对外开放 App 会员或 API 销售前切换官方或获授权 API。YLVEN 是订单、支付、退款、不可变账本、套餐和权益的唯一权威；Sub2API 接收执行投影，不能独立形成第二套冲突账本。

## 6. 架构决策

首期采用模块化 Core API + 独立 AI Runtime + Developer Gateway + Worker + Scheduler，而不是预先拆分几十个微服务。无状态请求服务可水平扩容；流式连接、队列和供应商并发池独立隔离。只有监控指标证明模块成为明确瓶颈后才抽离新服务。

## 7. 交付决策

P00～P13 每阶段必须有真实 APK、后台可见进展、功能清单、测试清单、部署记录、Owner Actions、构建信息和 SHA-256。Codex 不能通过聊天宣布完成，也不能因检查工作长期取代编码。项目所有者主要负责外部账号配置、APK 真机体验和后台验收。

## 8. 变更流程

本章程中的产品边界、身份方式、数据权威、财务原则、一级导航、域名和交付合同不得在实现中静默改变。确需改变时必须新增 ADR，列出原因、替代方案、数据迁移、API/Android/后台影响、回滚办法和项目所有者批准。
