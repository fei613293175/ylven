- `P03-022` — 复制整条回答

不在上述 Feature ID 中的功能不得因为效果图、示例文案或模型推测而新增。需要新增功能时，必须先更新 `contracts/feature-map.yaml`、页面合同和效果图绑定。

## 4. 效果图与功能的权威边界

1. 效果图只决定布局、层级、字号、行高、圆角、边距、高度、间隙、色值、组件位置和可见状态。
2. 功能、接口、数据库、权限、计费、异步任务和导航由 Feature ID 与开发文档决定。
3. 效果图中的用户名、金额、模型名、文件名、日期和聊天内容均为虚拟样例，不得写死进产品，也不得据此创造功能。
4. 效果图中出现但没有 `ui-interaction-map.csv` Interaction ID 的控件，只能作为装饰或禁用示意；Codex不得擅自赋予点击行为。
5. 开发文档要求但当前效果图未展示的功能不得被删除；应先提出视觉合同变更并补充效果图。
6. 数值冲突时，`ui-design-tokens.yaml` 和逐页 resolved contract 优先于对图片的肉眼估算；功能冲突时 `feature-map.yaml` 优先于效果图文案。

## 5. 实施顺序

1. 运行 UI 合同规划校验：`.\ylven.ps1 py scripts/19_VALIDATE_UI_CONTRACTS.py --mode planning`。
2. 读取本工作包全部 Feature ID 和绑定页面合同。
3. 运行视觉门禁：`.\ylven.ps1 py scripts/20_CHECK_UI_VISUAL_GATE.py --packet P03-W04`。
4. 若门禁未通过，只实施非视觉工作并记录 `BLOCKED_VISUAL`；禁止凭空画页面。
5. 门禁通过后，使用统一组件实现，不得在页面内硬编码新的字号、颜色、圆角或间距。
6. 对每个状态生成真实运行截图，填写 `UI_SCREENSHOT_INDEX.csv`。
7. 对照效果图完成像素验收并填写 `VISUAL_DIFF_REPORT.md`；差异需要修复或书面批准，不能只写“基本一致”。
8. 完成相关测试和原子提交后，进入同阶段下一工作包；项目所有者只在阶段末验收 APK 和后台。

## V1.6 强制版本连续性、关闭记录与执行环境规则

1. **新会话先恢复，不猜版本。** 新 Codex 会话、上下文压缩恢复、切换分支或 `git pull` 后，第一条命令固定为 `.\ylven.ps1 resume`。只能开发控制器输出的 `CURRENT_PHASE.yaml` 与 `CURRENT_WORK_PACKET.yaml`；聊天中的“继续下个版本”没有状态效力。
2. **定义与状态严格分离。** `contracts/work-packet-map.yaml` 只定义范围；`status/WORK_PACKET_STATUS.yaml` 是唯一可变工作包状态表；禁止再创建第二份当前阶段、当前工作包、状态表、历史或版本总账。
3. **代码写完不等于工作包关闭。** 当前包绑定的 Feature 必须具有最终状态、原因/证据和真实测试记录，代码与测试必须形成干净的实现 Commit，然后执行 `.\ylven.ps1 close-packet -Packet <当前WorkPacketID>`。控制器追加哈希链 `WORK_PACKET_HISTORY.jsonl`、更新运行状态、创建状态 Commit、尝试推送并机械选择下一包。
4. **外部原因延期必须留痕。** 只有真实外部依赖才可执行 `.\ylven.ps1 defer-packet -Packet <当前WorkPacketID> -Reason <具体原因>`；不得用延期掩盖未实现代码、未运行测试或缺失证据。
5. **阶段完成不等于正式版本关闭。** 全部工作包最终化后，阶段只能进入 `READY_FOR_RELEASE`。先执行 `.\ylven.ps1 release -Phase <当前阶段>`，在线上服务器从精确 Commit 构建 APK，下载后复核 SHA-256，再在项目所有者本机已连接的物理 Android 手机上执行覆盖安装、真实点击/输入/返回/滚动、关键流程、日志、逐状态截图和视觉回归；只交付同一服务器构建且真机验收通过的 APK。
6. **项目所有者批准后才关闭正式版本。** `OWNER_ACCEPTANCE.md` 含 `- Result: APPROVED`，且版本、Commit、CI Run、Artifact、APK SHA-256 一致后，执行 `.\ylven.ps1 close-release -Phase <当前阶段>`。控制器创建/校验不可变 Tag、追加哈希链 `RELEASE_LEDGER.jsonl`、创建状态 Commit并推进到相邻阶段第一个未完成包。
7. **仓库公开是项目事实，不是阻塞。** 当前仓库由项目所有者确认为 Public。每次提交、推送和发布前必须运行公开仓库 Secret 门禁；服务器地址、SSH 信息、密钥、签名材料、管理员一次性密码、Cloudflare/数据库/API 凭据只能放在本地忽略目录、GitHub Environment 或服务器秘密存储中。
8. **首次空仓库是正常初始化场景。** 缺少 `.git`、远端为空、没有默认分支时运行 `.\ylven.ps1 bootstrap`；Bootstrap 自动初始化 `main`、绑定唯一 `origin`、完成安全扫描并尝试首次推送。推送鉴权失败只阻塞远程 CI，不阻塞本地合同和代码工作。
9. **本机是轻量控制端。** 本机只要求 PowerShell、Git、uv、Spec Kit、OpenSSH；缺少 Java、Go、Gradle、Android SDK、Docker、Node 或系统 Python不得列为业务阻塞。线上服务器执行 Android 构建、重型自动测试、Docker、数据库和 staging 集成；本机真机验收必须使用 ADB，可使用仓库忽略目录中的 platform-tools。设备不可用时停止，设备被占用时进入共享 FIFO 等待；禁止 GitHub Actions、Android Emulator 和任何模拟器。
