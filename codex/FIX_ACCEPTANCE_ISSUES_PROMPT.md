# 修复当前阶段真机或后台验收问题

继续修复 YLVEN 当前阶段，不要创建新阶段、恢复复杂治理或重新规划整个项目。

1. 从 `CURRENT_PHASE.yaml` 确认阶段，读取该阶段文件、Feature Status、OWNER_ACCEPTANCE.md、用户提供的复现信息和受影响代码。
2. 将每个问题绑定到现有 Feature ID；确实不存在时先补 Feature Map、测试和阶段文档，再实现，不得创建无法追踪的临时功能。
3. 先复现，记录设备/环境、操作步骤、实际结果、预期结果、request_id、日志和最小根因。无法本地复现时建立能验证假设的日志或自动测试。
4. 修复最小必要纵向范围：Android、接口、数据库、后台、错误映射和测试需要一致，不能只改文案掩盖后端问题。
5. 对每个缺陷补回归测试；只运行受影响测试，修复完成后再运行阶段必要检查。
6. 更新 `status/<phase>_FEATURE_STATUS.yaml`、实施状态和 CHANGELOG 信息，重新执行发布与验证脚本，覆盖当前阶段交付目录。
7. 返回修复项、根因、测试、APK 路径、后台地址和仍需项目所有者验证的步骤，然后停止；不要进入下一阶段。
