# 多服务器分布式就绪架构

当前允许单服务器 staging，但代码从 P03 起必须满足水平扩容，避免后续重写会话和流式链路。

## 服务边界

- Cloudflare / 负载均衡入口；
- 多实例 Core API / Mobile BFF；
- 多实例 AI Runtime；
- 多实例 Developer Gateway；
- PostgreSQL 作为持久事实源；
- Redis/NATS 作为共享缓存、锁、限流和运行事件流；
- R2 作为共享文件与作品存储；
- Worker 多实例消费任务队列；
- Sub2API/官方 API Adapter 作为上游路由。

## P03 立即落实

- AI Runtime 无状态；
- `run_id + event_cursor` 支持跨实例 SSE 恢复；
- 会话锁和幂等键不依赖本地内存；
- 所有运行事件进入共享事件流并最终落库；
- 附件不依赖单机磁盘；
- 重试不得重复写消息、重复调用或重复扣费；
- 每个实例能够在没有 Sticky Session 的情况下接管恢复请求。

## 禁止

- 将会话历史、正在生成的完整状态或任务进度只放在某个进程内存；
- 用某台服务器本地目录保存正式附件；
- 多节点分别维护不同模型、价格、限流或 Secret 配置；
- 依赖手工登录某一台机器修改生产代码。
