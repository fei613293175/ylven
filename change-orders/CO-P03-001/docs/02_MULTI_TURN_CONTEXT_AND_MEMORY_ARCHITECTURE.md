# 多轮上下文与分层记忆架构

## 唯一事实源

YLVEN PostgreSQL 中的规范化会话记录是唯一事实源。Sub2API、OpenAI、Claude、Grok 的 `response_id`、conversation ID 或缓存只能作为优化，不能成为唯一会话记录。

## P03 必须落地的层次

1. **原始会话事实**：用户可见消息、AI 最终回答、附件、工具调用/结果、引用、模型、推理档位、时间、Token、状态、分支。
2. **最近完整轮次**：短对话直接发送全部当前分支历史；长对话按 Token 预算从最新向前保留完整轮次，不从一轮中间截断。
3. **结构化会话状态**：当前目标、已确认事实、决定、约束、未解决问题、活跃实体、已被替代事实。
4. **可追溯摘要**：较早消息分段压缩，保存来源消息范围、摘要模型和版本；原始消息不得删除。
5. **Provider continuation 旁路**：同一模型/同一通道可尝试上游续聊；失败、过期、切模型或网关不支持时，自动使用 YLVEN 本地历史重建。

## 上下文编译顺序

1. 系统安全与产品指令；
2. 当前模型适配指令；
3. 用户自定义指令；
4. 当前项目指令（项目阶段启用）；
5. 当前会话结构化状态；
6. 当前问题相关的历史摘要/情节；
7. 最近完整对话；
8. 当前附件与工具状态；
9. 本次用户消息。

## Token 预算

可用输入预算 = 模型上下文上限 − 输出预留 − 推理预留 − 工具预留 − 安全余量。不得用“固定最近 20 条”替代 Token 预算。

初始水位：

- <60%：尽量保留完整历史；
- 60%～75%：生成或更新较早区间摘要；
- >75%：摘要 + 最近完整轮次 + 相关检索；
- >90%：强制压缩后再调用。

具体阈值由后台动态配置和真实评测调整。

## 分支与多模型

每条消息预留 `parent_message_id`、`branch_id`、`comparison_group_id`。用户从某个候选回答继续时，只编译所选分支。切换 GPT、Claude、Grok 时，从同一中立会话事实重新转换供应商格式，禁止跨模型传播隐藏思维链或供应商内部 item ID。
