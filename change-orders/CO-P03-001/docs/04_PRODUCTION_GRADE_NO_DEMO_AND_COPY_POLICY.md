# 正式运营、无 Demo 与用户文案全局规则

## 全部阶段强制生效

前端、后端、管理后台、公共 API 和异步 Worker 都以真实运营为目标。阶段性未开放能力可以通过 Feature Flag 隐藏，但不得交付看似可用却使用假数据或空实现的页面。

## 普通用户 App 严禁

- `demo`、`test`、`mock`、`stub`、`placeholder`、`TODO`、`debug`；
- `streaming`、`connecting`、`provider error`、`HTTP 500`、`SSE`、`WebSocket`、`request id`；
- `Sub2API`、OAuth 账号池、内部路由名、数据库表名、队列名；
- “请输入智能推荐”“请输入默认模型”等把配置对象错误渲染为文本输入；
- 静态写死的用户、余额、模型、会话、统计数字和成功结果。

## 用户可见文案原则

文案必须说明用户正在经历什么以及可以做什么：

- `CONNECTING` → `正在思考`
- `RECONNECTING` → `连接不稳定，正在恢复…`
- `RATE_LIMITED` → `当前请求较多，请稍后再试`
- `PROVIDER_ERROR` → `暂时无法完成回答，请重试`
- `OFFLINE` → `当前网络不可用`

原始错误码、请求 ID 和供应商信息可以写入日志与后台诊断，但普通用户只在“问题详情”折叠区看到经过脱敏的支持编号，默认不展示。

## 后端严禁

- 生产路由返回固定假 JSON 冒充实现；
- 业务状态只存单实例内存；
- 跳过数据库迁移、鉴权、权限、幂等、审计、超时和错误映射；
- 测试适配器或假模型在生产配置可被普通流量调用；
- 成功响应先返回、真实持久化失败后不补偿。

## 发布门禁

每次正式 APK/后台发布前运行普通用户文案扫描、Stub/Demo 扫描、真实接口健康检查、数据库迁移测试、模拟器交互和效果图视觉比对。任何命中必须修复或由项目所有者书面批准明确例外；不得以“后续版本再改”为理由关闭当前包含该功能的阶段。
