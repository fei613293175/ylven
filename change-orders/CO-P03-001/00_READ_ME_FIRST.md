# YLVEN P03 多轮上下文、首页/会话体验与正式运营修正包

**变更单：`CO-P03-001`**  
**适配基线：YLVEN 开发计划包 V1.6.0；实际代码仓库处于 P03 且 P03 尚未正式关闭。**

## 这不是整套开发包重做

本包是针对当前已开发 P03 和后续全局规则的正式增量修正包。它不会推翻 P00～P03 已完成代码，也不允许与旧规则长期并行。导入后，指定旧页面、旧效果图和旧文案立即失效；P03 新增 `P03-W06`、`P03-W07`、`P03-W08`，完成后才允许关闭 P03。

## 执行顺序

1. Codex先完成当前正在执行的原 P03 Work Packet，并形成干净基线提交。
2. **不得执行 `close-release P03`，不得推进 P04。**
3. 将本包交给 Codex，执行 `python scripts/install_change_order.py --repo <真实仓库路径>`。
4. 新会话先恢复仓库状态：Windows PowerShell 执行 `.\ylven.ps1 resume`；Linux 服务器使用 PowerShell 7 时执行 `pwsh ./ylven.ps1 resume`。实际命令见 `codex/START_CHANGE_ORDER_PROMPT.md`。
5. 按顺序实施 `P03-W06 → P03-W07 → P03-W08`。
6. GitHub Actions完成多轮上下文、自动标题、全按钮、模拟器、截图和视觉回归。
7. 交付同一 CI Artifact 的 P03 APK、功能完成清单、自动测试和项目所有者测试清单。
8. 项目所有者真机与后台验收后，才允许关闭 P03。

## 全局生产规则

本包把以下规则提升为当前及后续全部阶段的发布门禁：

- 不得交付 Demo、测试壳、静态假数据、伪成功接口或内存临时业务状态。
- 普通用户界面不得出现 `streaming`、`connecting`、`provider error`、`request id`、`SSE`、`Sub2API`、`debug`、`demo`、`mock` 等技术性或调试性文案。
- 后台和开发者中心可以在权限控制下展示必要技术诊断，但不得展示模型隐藏思维链。
- 单服务器可以作为当前部署形态，但所有会话、任务、SSE 和文件架构必须从现在开始满足未来多服务器水平扩容。
