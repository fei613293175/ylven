# P10 产品套餐、钱包账本、权益与 Sub2API 投影

> 本阶段包含 **30 个 Feature ID**。本文件与 `contracts/feature-map.yaml` 一致；表中任何条目都不能仅以页面占位、静态返回或聊天声明视为完成。

## 1. 阶段目标

建立统一订单、支付抽象、不可变账本、额度桶、用量计费、套餐权益和 Sub2API 单向同步与对账。

## 2. 阶段边界

- 只实现本文件列出的 Feature ID；下一阶段内容不得为了“顺手”提前改变数据契约。
- 每个可见功能必须同时完成必要的 Android/网页状态、后端接口或内部事件、持久化、管理后台控制、权限、日志指标和测试。
- 外部凭据缺失时完成 Adapter、契约 mock、feature flag 和 Owner Actions；仅真实联调条目标记 `BLOCKED_EXTERNAL`。
- 不使用永久假数据、固定余额、固定模型列表、静态成功响应或不可追踪占位作品。
- 阶段发布前，所有本阶段 Feature 状态必须是 `IMPLEMENTED`、`DEFERRED_WITH_REASON` 或 `BLOCKED_EXTERNAL`。

## 4. Feature 逐项实施合同

### P10-001 — 后台创建产品、套餐和价格版本

- **产品表面/页面或菜单**：`Admin` / `商业化/产品与套餐`。
- **用户或管理员动作**：后台创建产品、套餐和价格版本。
- **必须覆盖的 UI/运行状态**：`idle|loading|success|empty|error`。所有状态均需可复现，错误态提供可恢复操作，不允许无限 Loading。
- **接口或事件合同**：`GET|POST` `/admin/v1/products`；负责服务为 `Catalog Service`。
- **数据实体**：`products|plans|prices`。数据库迁移、唯一约束、索引、所有权字段和删除策略必须与该能力一致。
- **管理后台控制**：`商业化/产品与套餐`。可变配置必须可查询、可审计；影响生产行为的配置需要版本和回滚。
- **权限**：`authenticated_user`；跨用户资源访问必须统一返回不可泄露资源存在性的错误。
- **计费规则**：`none`；收费动作必须在任务开始前完成预算校验/冻结，并在成功、失败或取消时结算或解冻。
- **异步任务**：`none`；若非 `none`，必须支持幂等提交、状态查询、超时、取消策略、重试上限和死信处理。
- **验收标准**：用户可在“商业化/产品与套餐”完成“后台创建产品、套餐和价格版本”，成功结果与服务端持久化状态一致；无权限、参数错误、重复提交、网络超时和服务异常均返回稳定错误码并呈现可恢复状态；管理后台“商业化/产品与套餐”能够查询或控制该能力，变更写入审计日志。
- **自动测试 ID**：`P10-001-UNIT|P10-001-API|P10-001-E2E`。测试结论必须落入阶段 TESTS.md，并能追溯到真实命令或日志。
- **实现补充**：遵循本阶段架构文档、OpenAPI、错误码目录和数据权威边界；发现合同冲突时先更新合同并记录 ADR，不能静默偏离。

## 6. 阶段不通过的典型情形

- APK 只是 Shell，Feature Map 中声称的链路没有真实后端或持久化。

- 页面、接口、数据库和管理后台使用不同字段含义，或模型能力被写死在 APK。
- 真实外部联调缺失却被标记 IMPLEMENTED，或者非关键外部配置阻塞整个阶段。

## V1.6 强制版本连续性、关闭记录与执行环境规则

1. **新会话先恢复，不猜版本。** 新 Codex 会话、上下文压缩恢复、切换分支或 `git pull` 后，第一条命令固定为 `.\ylven.ps1 resume`。只能开发控制器输出的 `CURRENT_PHASE.yaml` 与 `CURRENT_WORK_PACKET.yaml`；聊天中的“继续下个版本”没有状态效力。
2. **定义与状态严格分离。** `contracts/work-packet-map.yaml` 只定义范围；`status/WORK_PACKET_STATUS.yaml` 是唯一可变工作包状态表；禁止再创建第二份当前阶段、当前工作包、状态表、历史或版本总账。
3. **代码写完不等于工作包关闭。** 当前包绑定的 Feature 必须具有最终状态、原因/证据和真实测试记录，代码与测试必须形成干净的实现 Commit，然后执行 `.\ylven.ps1 close-packet -Packet <当前WorkPacketID>`。控制器追加哈希链 `WORK_PACKET_HISTORY.jsonl`、更新运行状态、创建状态 Commit、尝试推送并机械选择下一包。
4. **外部原因延期必须留痕。** 只有真实外部依赖才可执行 `.\ylven.ps1 defer-packet -Packet <当前WorkPacketID> -Reason <具体原因>`；不得用延期掩盖未实现代码、未运行测试或缺失证据。
5. **阶段完成不等于正式版本关闭。** 全部工作包最终化后，阶段只能进入 `READY_FOR_RELEASE`。先执行 `.\ylven.ps1 release -Phase <当前阶段>`，让 GitHub Actions 对精确 Commit 构建、模拟器点击测试、升级安装、截图和视觉回归，并交付同一 CI Artifact。
6. **项目所有者批准后才关闭正式版本。** `OWNER_ACCEPTANCE.md` 含 `- Result: APPROVED`，且版本、Commit、CI Run、Artifact、APK SHA-256 一致后，执行 `.\ylven.ps1 close-release -Phase <当前阶段>`。控制器创建/校验不可变 Tag、追加哈希链 `RELEASE_LEDGER.jsonl`、创建状态 Commit并推进到相邻阶段第一个未完成包。
7. **仓库公开是项目事实，不是阻塞。** 当前仓库由项目所有者确认为 Public。每次提交、推送和发布前必须运行公开仓库 Secret 门禁；服务器地址、SSH 信息、密钥、签名材料、管理员一次性密码、Cloudflare/数据库/API 凭据只能放在本地忽略目录、GitHub Environment 或服务器秘密存储中。
8. **首次空仓库是正常初始化场景。** 缺少 `.git`、远端为空、没有默认分支时运行 `.\ylven.ps1 bootstrap`；Bootstrap 自动初始化 `main`、绑定唯一 `origin`、完成安全扫描并尝试首次推送。推送鉴权失败只阻塞远程 CI，不阻塞本地合同和代码工作。
9. **本机是轻量控制端。** 本机只要求 PowerShell、Git、uv、Spec Kit、OpenSSH，发布下载时使用 GitHub CLI；缺少 Java、Go、Gradle、ADB、Android SDK、Docker、Node 或系统 Python不得列为业务阻塞。构建、模拟器和视觉回归在 GitHub Actions；Docker、数据库和 staging 集成在已连接线上服务器执行。
10. **本机 Git 推送失败时的固定备用路径。** 保持同一 Commit SHA、阶段分支和 `origin` 不变，通过已验证的 SSH/SFTP 将完整 Git Bundle 传到服务器，校验 SHA-256 与 `git bundle verify` 后由服务器推送 GitHub；不得把 Token、密钥或 Secret 放入仓库、Bundle、命令行或日志，推送后必须回读 GitHub 分支 SHA。
10. **快速执行优先。** 每个工作包只做一次必要预检，随后直接编码并运行受影响测试；输入未变化时禁止重复全仓库审计。产出优先级固定为：可运行代码 → 自动测试 → 必需合同 → 必需说明。
11. **每版交付必须可追溯。** 桌面交付只能来自通过 CI 的精确 Artifact，并包含计划功能、完成功能、自动测试、项目所有者测试清单、截图索引、视觉差异、端点与 DNS 状态、Build Info、CI Provenance、已知问题和 SHA-256。

## 正式运营、无 Demo、用户文案与分布式就绪规则

1. 前后端必须按真实运营实现；禁止 Demo、Stub、Mock、静态假数据、伪成功接口和仅内存业务状态。
2. 普通用户界面不得出现 streaming、connecting、provider error、request id、SSE、Sub2API、debug、demo、mock 等技术或测试词；必须映射为普通用户可理解且可恢复的文案。
3. 页面必须使用已批准效果图和固定 UI Token；样例文字不创造功能，功能不得因效果图未展示而删除。
4. 当前可单服务器运行，但 API、AI Runtime、SSE、任务和文件必须满足未来多实例接管；正式状态不得只保存在单节点。
5. 发布前必须通过真实数据库/接口、权限、幂等、迁移、普通用户文案、模拟器交互、截图视觉和 CI Artifact 来源验收。
6. 多写实际代码与测试，少做重复审计；输入未变化时不得循环执行全仓库检查代替实现。
