# P06 项目空间、知识库、检索与引用

> 本阶段包含 **20 个 Feature ID**。本文件与 `contracts/feature-map.yaml` 一致；表中任何条目都不能仅以页面占位、静态返回或聊天声明视为完成。

## 1. 阶段目标

让项目聚合会话、文件、作品、指令和知识索引，并提供可解释检索、上下文预算与引用。

## 2. 阶段边界

- 只实现本文件列出的 Feature ID；下一阶段内容不得为了“顺手”提前改变数据契约。
- 每个可见功能必须同时完成必要的 Android/网页状态、后端接口或内部事件、持久化、管理后台控制、权限、日志指标和测试。
- 外部凭据缺失时完成 Adapter、契约 mock、feature flag 和 Owner Actions；仅真实联调条目标记 `BLOCKED_EXTERNAL`。
- 不使用永久假数据、固定余额、固定模型列表、静态成功响应或不可追踪占位作品。
- 阶段发布前，所有本阶段 Feature 状态必须是 `IMPLEMENTED`、`DEFERRED_WITH_REASON` 或 `BLOCKED_EXTERNAL`。

## 3. 建议的纵向实施顺序

1. **Admin 纵向切片**：`P06-019`, `P06-020`。先完成最小可运行链路，再补异常状态、后台控制、观测和测试。
2. **Android 纵向切片**：`P06-001`, `P06-002`, `P06-003`, `P06-004`, `P06-005`, `P06-006`, `P06-007`, `P06-008`, `P06-009`, `P06-014`, `P06-015`, `P06-016`, `P06-017`。先完成最小可运行链路，再补异常状态、后台控制、观测和测试。
3. **Backend 纵向切片**：`P06-012`, `P06-013`, `P06-018`。先完成最小可运行链路，再补异常状态、后台控制、观测和测试。
4. **Worker 纵向切片**：`P06-010`, `P06-011`。先完成最小可运行链路，再补异常状态、后台控制、观测和测试。

### P06-001 — 分页展示项目列表

- **产品表面/页面或菜单**：`Android` / `工作/项目`。
- **用户或管理员动作**：分页展示项目列表。
- **必须覆盖的 UI/运行状态**：`idle|loading|success|empty|error`。所有状态均需可复现，错误态提供可恢复操作，不允许无限 Loading。
- **接口或事件合同**：`GET` `/api/mobile/v1/projects`；负责服务为 `Project Service`。
- **数据实体**：`projects`。数据库迁移、唯一约束、索引、所有权字段和删除策略必须与该能力一致。

- **权限**：`authenticated_user`；跨用户资源访问必须统一返回不可泄露资源存在性的错误。

## V1.6 强制版本连续性、关闭记录与执行环境规则

1. **新会话先恢复，不猜版本。** 新 Codex 会话、上下文压缩恢复、切换分支或 `git pull` 后，第一条命令固定为 `.\ylven.ps1 resume`。只能开发控制器输出的 `CURRENT_PHASE.yaml` 与 `CURRENT_WORK_PACKET.yaml`；聊天中的“继续下个版本”没有状态效力。
2. **定义与状态严格分离。** `contracts/work-packet-map.yaml` 只定义范围；`status/WORK_PACKET_STATUS.yaml` 是唯一可变工作包状态表；禁止再创建第二份当前阶段、当前工作包、状态表、历史或版本总账。
3. **代码写完不等于工作包关闭。** 当前包绑定的 Feature 必须具有最终状态、原因/证据和真实测试记录，代码与测试必须形成干净的实现 Commit，然后执行 `.\ylven.ps1 close-packet -Packet <当前WorkPacketID>`。控制器追加哈希链 `WORK_PACKET_HISTORY.jsonl`、更新运行状态、创建状态 Commit、尝试推送并机械选择下一包。
4. **外部原因延期必须留痕。** 只有真实外部依赖才可执行 `.\ylven.ps1 defer-packet -Packet <当前WorkPacketID> -Reason <具体原因>`；不得用延期掩盖未实现代码、未运行测试或缺失证据。
5. **阶段完成不等于正式版本关闭。** 全部工作包最终化后，阶段只能进入 `READY_FOR_RELEASE`。先执行 `.\ylven.ps1 release -Phase <当前阶段>`，让 GitHub Actions 对精确 Commit 构建、模拟器点击测试、升级安装、截图和视觉回归，并交付同一 CI Artifact。
6. **项目所有者批准后才关闭正式版本。** `OWNER_ACCEPTANCE.md` 含 `- Result: APPROVED`，且版本、Commit、CI Run、Artifact、APK SHA-256 一致后，执行 `.\ylven.ps1 close-release -Phase <当前阶段>`。控制器创建/校验不可变 Tag、追加哈希链 `RELEASE_LEDGER.jsonl`、创建状态 Commit并推进到相邻阶段第一个未完成包。

8. **首次空仓库是正常初始化场景。** 缺少 `.git`、远端为空、没有默认分支时运行 `.\ylven.ps1 bootstrap`；Bootstrap 自动初始化 `main`、绑定唯一 `origin`、完成安全扫描并尝试首次推送。推送鉴权失败只阻塞远程 CI，不阻塞本地合同和代码工作。

10. **本机 Git 推送失败时的固定备用路径。** 保持同一 Commit SHA、阶段分支和 `origin` 不变，通过已验证的 SSH/SFTP 将完整 Git Bundle 传到服务器，校验 SHA-256 与 `git bundle verify` 后由服务器推送 GitHub；不得把 Token、密钥或 Secret 放入仓库、Bundle、命令行或日志，推送后必须回读 GitHub 分支 SHA。
